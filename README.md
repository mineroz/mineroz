# Mako Production System

Tooling for rebuilding the Petowal Mining Company operation reporting from scratch:
an Excel phase the site team can run now, followed by a web application on Resolute servers.
Both phases are driven by one data model, `mps/schema/mps_schema.json`.

## Quick start (Windows)

1. Save `Setup-MakoPS.ps1` anywhere on C:.
2. Open a normal PowerShell window (not "Run as administrator": mapped drives such as X:
   are not visible in an elevated session) and run:

   ```powershell
   powershell -ExecutionPolicy Bypass -File .\Setup-MakoPS.ps1
   ```

   It creates `C:\MakoPS` with `01_Tools`, `02_Source\2026`, `03_Inspection` and `04_MPS`,
   writes the tooling, installs Python 3 for the current user if none is present, copies the
   2026 PMC workbooks from the X: drive as working copies, runs the audit and builds the
   MPS workbooks:

   | File | Purpose |
   |---|---|
   | `C:\MakoPS\04_MPS\MPS_2026.xlsx` | blank workbook for production use |
   | `C:\MakoPS\04_MPS\MPS_2026_DEMO.xlsx` | same workbook with 74 days of synthetic data, for training and review |

3. Open the DEMO workbook first, then read the README sheet in the blank workbook before
   the first entry.
4. Share `C:\MakoPS\03_Inspection` (report plus JSON files) for review. It holds structure
   only: sheet names, links, formula counts, defined names, VBA procedure names. No
   production figures, no VBA source.

Switches: `-SkipCopy` (workbooks already in `02_Source\2026`), `-SkipRun` (no audit),
`-SkipBuild` (no MPS workbooks), `-Year 2027`, `-Root D:\MakoPS`.

## Daily use

All scripts live in `C:\MakoPS\01_Tools` and are documented in `tools/README.md`.

| Script | What it does |
|---|---|
| `Build-MPS.ps1` | rebuilds `04_MPS\MPS_<year>.xlsx` and the DEMO workbook from the schema (close them in Excel first) |
| `Export-DailyReport.ps1` | sets the date in `Daily_Report!C5`, lets Excel calculate and exports the sheet to `04_MPS\Reports\Mako_Daily_Report_yyyy-MM-dd.pdf`; `-Email -To ...` opens an Outlook mail with the PDF attached for review |
| `Invoke-XlInspect.ps1` | refreshes the structural audit of the PMC workbooks in `02_Source\2026` |
| `PythonEnv.ps1` | shared Python discovery and installation, dot-sourced by the scripts above |

```powershell
C:\MakoPS\01_Tools\Export-DailyReport.ps1                              # yesterday's report
C:\MakoPS\01_Tools\Export-DailyReport.ps1 -Date 2026-03-15 -Open
C:\MakoPS\01_Tools\Export-DailyReport.ps1 -Email -To gm@example.com
```

Excel is required for the PDF export (COM automation, no macros in the workbook); classic
Outlook for `-Email`. The scripts target Windows PowerShell 5.1 and need no admin rights.

## Repository layout

| Path | Purpose |
|---|---|
| `Setup-MakoPS.ps1` | Self-contained bootstrap. Generated by `tools/build_setup.py`, do not edit by hand. |
| `mps/schema/mps_schema.json` | The data model: input tables, lists, reference tables, calculations. Drives the workbook and the SQL schema. |
| `mps/build_workbook.py` | Generates the MPS workbook from the schema (`--sample-days N` for DEMO data). |
| `mps/build_ddl.py`, `mps/validate_workbook.py`, `mps/sql/` | SQL schema generator, workbook validator (LibreOffice recalculation), generated DDL. See `mps/README.md`. |
| `tools/PythonEnv.ps1` | Python discovery and per-user installation (UTF-8 with BOM, CRLF). |
| `tools/Invoke-XlInspect.ps1` | Runs the workbook audit. |
| `tools/Build-MPS.ps1` | Builds the MPS workbooks into `04_MPS`. |
| `tools/Export-DailyReport.ps1` | Daily_Report to PDF via Excel, optional Outlook mail. |
| `tools/xl_inspect.py` | Workbook structural audit. See `tools/README.md`. |
| `tools/build_setup.py` | Rebuilds and verifies `Setup-MakoPS.ps1` from the files in `tools/` and `mps/`. |
| `docs/` | Generated documentation such as the data dictionary. |
| `data/2026/` | Placeholder only. Workbooks stay on C: and X:, never in this public repository. |

After changing any file that `Setup-MakoPS.ps1` embeds, run `python tools/build_setup.py`
and commit the regenerated bootstrap with it.

This repository is public. Do not commit site data to it.
