# Mako Production System data dictionary

Mako Gold Mine, Petowal Mining Company S.A. (owner Resolute Mining Limited), Senegal. Generated from `mps/schema/mps_schema.json` version 0.3.0 by `mps/build_ddl.py`; the same schema generates the Excel workbook (`mps/build_workbook.py`). Do not edit this file; change the schema and regenerate.

Conventions: metric units, tonnes dry, grades in g/t, gold in troy ounces (31.1035 g), percentages stored as fractions between 0 and 1, dates are production days (day shift start to night shift end), site time zone GMT. Blank (NULL) means not reported; zero means reported as zero.

Rules applied by the generator:

- Table names drop the `tbl` prefix and become snake_case; tables with one row per day get the suffix `_daily`. Column names are the Excel field names in lower case.
- Primary key: the date or month column of the tables prefilled with one row per period; an `id` column (`BIGSERIAL` in PostgreSQL, `INTEGER PRIMARY KEY AUTOINCREMENT` in SQLite) elsewhere. Natural keys: `movement` (date, shift, source, material, destination); `fleet` (date, equipment_class). Where a natural-key column is optional (movement shift, blank for a daily total) the uniqueness is a unique index on `COALESCE(column, '')` so that two daily totals cannot be entered twice.
- `NOT NULL` for required and key fields. `CHECK` constraints from the schema min and max; Excel only warns, SQL rejects. Month columns must be the first day of the month.
- List fields reference `ref_<list>` tables seeded with the drop-down values in order (`sort_order`). `movement.source` and `movement.destination` reference the `sources` and `destinations` tables; `stockpiles.stockpile` must exist in both.
- Calculated fields with an SQL expression are generated columns (`GENERATED ALWAYS AS ... STORED` in PostgreSQL, `VIRTUAL` in SQLite, where numeric operands are cast to `REAL` to avoid integer division). Lookups into reference tables (source type, destination type) are `LEFT JOIN`s in the `<table>_calc` views, and SQLite also puts there anything it cannot generate. Generated columns carry no CHECK constraint: validation applies to inputs only.
- Excel-only report helpers are not carried to SQL: `tblSafetyHistory.Use`, `tblCommentary.Seq_Day`, `tblCommentary.Key_Day`.
- Every table except the `ref_*` lists carries `created_at`, `updated_at` (kept current by a trigger) and `updated_by TEXT`.
- `kpi_daily` reproduces the workbook Calc_Daily day columns from the KPI catalogue in `build_workbook.py`; `kpi_monthly` groups it by month with ratios recomputed from the summed numerators and denominators. Both views are recreated by every run of the script.
- Both scripts are idempotent (`IF NOT EXISTS`, seeds inserted only when missing, views recreated). Structural changes to a populated database need a migration.

## KPI catalogue

Columns of the `kpi_daily` view (one row per date with data), in the order of the workbook KPI catalogue. Sum KPIs are day totals (0 when no rows); ratio KPIs are numerator over denominator for the day and NULL when the denominator is 0; `kpi_monthly` recomputes ratios from monthly sums, which is how the workbook builds month-to-date figures. Ex-pit means source type Pit, ore means a material starting with Ore, rehandle means source type Stockpile.
